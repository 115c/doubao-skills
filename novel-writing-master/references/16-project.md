# 16 · 工程化：目录、状态机、断点续写、日更批次

> 长篇写到 30 万字，靠记忆一定崩。**靠目录结构和一份状态 JSON。**
> 原则：数据只有一处真源，派生文件不许手改。

## 一、标准目录

```
{书名}/
├── 设定/
│   ├── 题材定位.md        # 01 的五件产出
│   ├── 世界观.md          # 02 的规则/代价/势力/标尺
│   ├── 人物.md            # 03 的人物卡
│   ├── 关系矩阵.md
│   └── 文风.md            # 语感、句长、称谓、禁用词
├── 大纲/
│   ├── 全书结构.md        # 04 的节拍表 + 章号
│   ├── 卷纲_第N卷.md
│   └── 章纲.md            # 05 的字段表
├── 正文/
│   └── 第0001章_标题.md
├── 追踪/
│   ├── _state.json        # 唯一真源（见第三节）
│   ├── 上下文.md          # 派生：当前局面速览
│   ├── 人物快照.md        # 派生
│   ├── 伏笔.md            # 派生自 promises/clues/questions
│   ├── promises.md
│   ├── clues.md
│   ├── questions.md
│   └── 时间线.md
├── .work/
│   ├── 原稿/              # 改稿前备份
│   └── 去味原稿/
└── 发布/
    ├── 书名简介标签.md
    └── 发布记录.md
```

**单文件短篇**例外：`设定.md`＋`小节大纲.md`＋`正文.md` 三件即可。

## 二、命名规范

- 章节：`第0001章_标题.md`（四位补零，保证排序）
- 备份：`{YYYYMMDD}_{原文件名}`
- 编号：`P001 / C001 / Q001`，只增不改
- 一个目录一个主题，不许出现"新建文件夹"

## 三、状态机（`追踪/_state.json`）

```json
{
  "book": {"title": "", "genre": "", "platform": "", "target_words": 0},
  "progress": {"volume": 1, "chapter": 12, "words_total": 0, "last_update": ""},
  "structure": {"model": "八步", "beats": {"激励": 3, "中点": 30, "低谷": 60, "高潮": 72}},
  "characters": {"主角": {"位置": "", "伤势": "", "资源": "", "已知": [], "目标": ""}},
  "ledger": {"promises": [], "clues": [], "questions": []},
  "bans": ["本章禁止发生的事"],
  "next": {"chapter": 13, "goal": "", "hook": ""}
}
```

**写入纪律**：

1. 每章写完立刻更新 `progress` 与 `characters` 变化项。
2. 派生文件由脚本或固定流程生成，**不许手改**（改了就会和真源打架）。
3. 提交前跑 `scripts/novel_check.py --state 追踪/_state.json`，字段缺失会报。

## 四、断点续写（中断三天以上必做）

1. 读 `_state.json` 的 `progress` 与 `next`。
2. 读最后一章正文**最后 300 字**（不是全章，抓语气与停笔点）。
3. 读 `上下文.md`（当前局面）与 `伏笔.md` 里未收的条目。
4. 读下一章章纲。
5. 写之前先口述一遍"谁在哪、要干什么、被谁挡、这章结束变成什么"，四问答全再落笔。

**恢复粒度不许降级**：原本是整章批次，不许改成"先写个片段试试"；占位、冒烟、诊断性质的半成品不算交付。

## 五、日更批次

| 项 | 规则 |
|---|---|
| 单轮章数 | 默认 1 章；明确说"日更"默认 2-3 章；**单轮最多 3 章** |
| 每章内循环 | 章纲 → 落笔 → 六维评分 → 一致性六查 → 机检 → 提交状态 |
| 批次结束 | 汇报"写了哪几章、各章结局局面、未收伏笔、下一章要写什么" |
| 不许 | 边写边改前面章节（要改走改稿流程，单独一轮） |

## 六、多书并行

- 一个项目多本书时，用 `.active-book` 文件记录当前书路径。
- 切书时先写状态再切，否则会把 B 书的进度写进 A 书。
- 跨书共享的只有：素材库、人名库、套路库；**人物与设定不共享**。

## 七、版本与备份

| 时机 | 动作 |
|---|---|
| 改稿前 | 原文复制到 `.work/原稿/{日期}_{原名}` |
| 每卷末 | 整卷快照（目录复制，不改名） |
| 大改结构前 | 先写 `结构变更说明.md`（改什么、影响哪几章、为什么） |
| 删除类操作 | 一律先列清单，等人拍板；不许自行批量删 |

## 八、批量排产（多章一次规划时）

1. 先出这一批的章纲表（每章一行，字段见 05 第十一节）。
2. 跑 `scripts/pacing_grid.py` 看节奏警告，改到无硬错误。
3. 再逐章写，**不许拿一份章纲连续套写三章**（会出现同型钩子与同型场景）。
4. 每章写完回头核一次：本章与上一章是不是同一个功能标签？连续三章同标签必须换。
