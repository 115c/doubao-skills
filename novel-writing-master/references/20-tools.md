# 20 · 机检脚本与检查清单

> 三个脚本，纯 Python 标准库，Windows 上直接 `python xxx.py`。
> 定位：**脚本只出线索，不做判决**。零命中不等于合格；命中也不等于必改。

## 一、`scripts/tracking_init.py` — 建项目骨架

```powershell
python tracking_init.py "D:\小说\我的书" --title 我的书 --genre 都市复仇 --platform 番茄 --target 1200000
python tracking_init.py "D:\小说\短篇集\第一篇" --short
python tracking_init.py "D:\小说\我的书" --force     # 只补缺，不覆盖已有内容
```

产出：`设定/ 大纲/ 正文/ 追踪/ 发布/ .work/`；唯一真源 `追踪/_state.json`；三本账 `promises.md / clues.md / questions.md`；`时间线.md`；派生文件 `上下文.md / 人物快照.md`；可直接解析的 `大纲/章纲.md` 表头。

**它不覆盖已有文件**（除非 `--force` 且目标文件为空），所以可以在已有项目上反复跑。

## 二、`scripts/pacing_grid.py` — 章纲节奏网格

```powershell
python pacing_grid.py 大纲\章纲.md
python pacing_grid.py 大纲\章纲.md --out grid.csv
python pacing_grid.py 大纲\章纲.md --json
```

识别表头关键词：章号／标题／功能标签／outcome／钩子／埋收／字数。

告警口径：

| 级别 | 条件 | 对应模块 |
|---|---|---|
| 阻断 | 章号重复或缺号 | 12 |
| 提示 | 连续 3 章 `outcome=yes`（没有压力） | 07 |
| 提示 | 连续 3 章钩子为 `resolution`／收束／空 | 08 |
| 提示 | 连续 3 章同一功能标签 | 05 |
| 提示 | 某章缺章尾钩子 | 08 |
| 提示 | 字数离群（>中位数 2 倍或 <一半） | 05 |

退出码：有阻断项返回 1，否则 0。

## 三、`scripts/novel_check.py` — 稿件与账本体检

```powershell
python novel_check.py 正文\第0001章.md
python novel_check.py 正文\ --json
python novel_check.py 正文\第0001章.md --no-ai      # 只做结构与标点
python novel_check.py --state 追踪\_state.json        # 状态机 schema + 伏笔超期
python novel_check.py --consistency 追踪\             # 章节缺号 + 账本未结
python novel_check.py --ledger 追踪\                  # 章纲「埋收」列 × 账本章号 对齐
```

**章号与章纲联动（v1.1 起默认生效）**：只要文件放在 `<项目>/正文/` 下，脚本会自动从文件名 `第0002章` 取章号、到 `<项目>/大纲/章纲.md` 读该章的字数区间与埋收列，再从 `追踪/_state.json` 的 `characters` 里取需记人名，统计本章首次出现的人名。无需手动指定；章号或章纲位置特殊时才用 `--chapter N` / `--outline <路径>` 覆盖。

单文件输出：净字数／中文字符／段落数／句数／平均句长／最长段，加三类命中。

| 类别 | 判据 | 处置 |
|---|---|---|
| 阻断 | 强信号词（他不知道的是／殊不知／命运的齿轮／意义深远／他终于明白…）、占位符、逐字重复句、连续 ≥5 句 ≤6 字的碎句、**净字数偏离章纲区间中值 ±20%** | 改到净，或登记白名单；字数必须回到区间 |
| 提示 | 弱信号 ≥8 处、长段 >320 字、8 字片段重复 ≥6 次、叙述段破折号、连续感叹号、半角标点、旁白省略号密度、`了下` 密度、**净字数偏离 ±10%**、**本章需记人名 >5**、**本章新增需记人名 >2**、**连续空行** | 回上下文判断 |
| 信息 | 字数低于 1500 或高于 4500、字数在区间内、本章新增人名清单、弱信号单次出现 | 只作参考 |

字数闸口口径：以章纲区间的中值为基准算偏差，**±10% 提示、±20% 阻断**。不盯死某一个数——区间本身就是弹性的；但一章冲出 ±20% 等于这章的疏密判断整段失效（写薄了事件不够，写厚了灌水），必须回到区间再交。

`--ledger` 的输出口径：比对章纲「埋收」列与 `_state.json` 的 `chapter`（埋）／`paid_at`（收）。**已写章的冲突报错误，尚未写到的那几章报警告**（章纲先规划、账本后登记属正常）。编号写错、账本里根本没有该编号的，已写章报错误。

退出码：有阻断返回 1。

### 白名单机制

作者**明确选定**的原句可以保留。做法：在 `设定/文风.md` 末尾加一节：

```
## 去味白名单
- "他听烦了，把杯子往桌上一放。"（作者要求保留的直写情绪）
```

登记后，该句命中不再计入 blocking，但报告里仍要说明保留了哪些、为什么。

## 四、四条使用纪律

1. **先跑脚本，再做人工三层扫描**（表达／用笔／故事），顺序不能反。
2. **不改到零为目标**：把有效表达删成残句也是病。
3. **脚本报 blocking 必须处理**：改到净，或按白名单保留并在报告里说明。
4. **脚本不可用要如实说**，不许宣称"已通过检查"。

## 五、交付前机检清单（13 条，逐条打勾）

- [ ] 1. `novel_check.py` 单章跑完，blocking = 0（或全部登记白名单）
- [ ] 2. 连续碎句 ≤4；长段 ≤320 字
- [ ] 3. 占位符、TODO、待补 = 0
- [ ] 4. 逐字重复句 = 0
- [ ] 5. `pacing_grid.py` 无阻断项（章号连续）
- [ ] 6. 本批章节 outcome 不出现连续 3 章 yes
- [ ] 7. 章尾钩子字段无空缺
- [ ] 8. `novel_check.py --state` 无错误（三本账齐全）
- [ ] 9. 未结伏笔已在报告里列出（超 20 章的必须说明怎么办）
- [ ] 10. 人工六维评分 ≥9 且无 0 分（见 13）
- [ ] 11. 净字数在章纲区间 ±10% 内（±20% 已阻断）
- [ ] 12. `novel_check.py --ledger` 已写章零错误；有冲突先在一处改定（章纲改账本、或账本改章纲），不许两处各记一个
- [ ] 13. **改稿后重跑三项**：再机检（blocking=0）、再核字数（回到区间）、再查重复句与连续空行

## 六、脚本不做的事（避免误用）

- 不做语义判断：它不认识"这句话好不好"，只认识"这个词出现过"。
- 不替你判定人物动机、结构位置、爽点强度——这些只能人工。
- 不自动改写：所有修改由人（或按 11 的流程）执行。
- 不检查平台合规：敏感内容按平台当期规则人工核。
