# 12 · 一致性：六种审查、三本账、一份状态机

> 长篇崩掉从来不是因为"写得不好"，是因为**忘了**。
> 这一层不是文笔问题，是数据问题：所有该记住的事必须有唯一存放位置，且只有一处。

## 一、六种一致性（每章完稿必查）

| # | 一致性 | 查什么 | 崩了的表现 |
|---|---|---|---|
| 1 | 剧情逻辑 | 关键事件有没有前提；关键决定有没有触发；关键变化有没有后果 | 人物突然让步、反派突然变傻 |
| 2 | 人物目标 | 主角这章到底想做什么，过程中有没有无故漂移 | 章中改主意无理由 |
| 3 | 情绪与关系 | 情绪有没有来路；关系温度和上一场对不对得上 | 昨天还在决裂，今天称兄道弟 |
| 4 | 身体与信息 | 伤势、疲劳、秘密、误会、已知信息有没有丢 | 断了的胳膊下一章提剑 |
| 5 | 场景与转场 | 读者会不会迷路；上一场余力有没有带到下一场 | 时空跳跃无交代 |
| 6 | 章末承接 | 章末有没有收在变化上；下一章第一拍能不能接住 | 上章留的钩子下章不提 |

**任意两项不稳，不许交付，先回对应模块修。**

## 二、三本账（每本只有一个存放位置）

| 类型 | 记什么 | 存放 | 状态机 |
|---|---|---|---|
| promise 承诺 | 契诃夫之枪、誓言、预言、死线、交易 | `追踪/promises.md` | `planned` → `planted`（第N章埋）→ `paid-off`（第N章收） |
| clue 线索 | 推理类线索、红鲱鱼 | `追踪/clues.md` | 同上，另记"公平性"（读者是否拿到同样信息） |
| question 悬念 | 读者被留下要问的问题 | `追踪/questions.md` | `open` → `answered`（第N章答） |

**纪律**：

1. 一条 setup **只能进一本账**，不许同时抄在两处。
2. 埋了不收＝欠债；每卷末对账，未收的写进下卷或在本卷收掉。
3. 编号只增不改，格式 `P001 / C001 / Q001`，正文提到时带编号。
4. 小暗示、意象呼应这类不需要机检回收的，记在**卷纲的伏笔表**里即可，不进三本账。

## 三、时间线

两套时间必须分开：

- **故事时间**（事件发生的先后顺序）：`追踪/时间线.md`，一行一件事。
- **叙述时间**（读者看到的顺序）：由章节顺序决定。

每条时间线记录格式：

```
| 故事时间 | 事件 | 关联线 | 章节 |
| 第3天清晨 | 接到退婚书 | 主线 | 第1章 |
| 十二年前 | 母亲把他抵给债主 | 人物 | —（回忆） |
```

**倒叙／插叙必须标**，否则后面写到"三天后"会和前文打架。

## 四、人物状态机（每章提交，只记变化）

```
{
  "chapter": 12,
  "characters": {
    "主角": {"位置":"城西","伤势":"左臂骨裂","资源":"三百两","暴露度":"半公开","已知":["账本在二房"],"目标":"拿到账本"},
    "配角A": {"关系温度":"冷","债务":"欠主角一条命"}
  },
  "relationship_changes": [{"a":"主角","b":"配角A","from":"僵","to":"冷","reason":"目睹主角撒谎"}],
  "debts_open": ["配角A 的救命之恩"],
  "foreshadow": {"planted":["P004","Q002"],"paid":["P001"]}
}
```

这份 JSON 是**唯一数据源**，`上下文.md`、`人物快照`、`伏笔.md`、`时间线` 都由它派生，禁止手改派生文件。

## 五、MICE 收口（判断是否烂尾）

四条线各有开合，开在谁身上就得在谁身上合（详见 05 第十节）。全书结局前逐条核：

- M 环境线：进了哪个世界／地图，离开了没有？
- I 疑问线：提了哪个谜，答了没有？
- C 人物线：谁对自己的处境不满，改变了没有？
- E 事件线：哪个危机开始了，结束了没有？

**漏合一条＝烂尾。最后 1-2 章不许开新线。**

## 六、跨卷／系列连续性

| 项 | 要求 |
|---|---|
| 跨卷奖励 | 上卷伏笔至少带 1-2 条进下卷，不许全部清零 |
| 旧角色 | 重要人物带过去；至少一个老角色在新地图重新出现 |
| 战力／资源 | 只增不倒退；若必须削弱，给出代价与解释 |
| 世界观 | 新地图可以加规则，**不许推翻旧规则**（推翻要写成"旧认知被揭穿"，并给证据） |
| 读者记忆 | 隔卷重提旧事时，用一句"场景化提示"（一个物件、一个称呼）唤醒，不复述前情 |

## 七、机检清单（跑 `scripts/novel_check.py --consistency`）

1. 三本账里 `planted` 未 `paid-off` 且已超 20 章的条目数。
2. 章节连号是否有缺口。
3. 人物快照里"死了"却仍在出场的人。
4. 时间线里倒序叙述未标注的条目。
5. 章纲 outcome 连续 3 章 `yes`。
6. 章尾钩子连续 3 章 `resolution`（收束型）。
7. 章末 `hook` 字段为空。

前 4 条是硬错误，后 3 条只是提示（提示的处置见 05 与 13）。
