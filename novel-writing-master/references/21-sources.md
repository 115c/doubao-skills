## 三、没采用的东西（以及为什么）

| 未采用 | 原因 |
|---|---|
| oh-story 的 Node 脚本与 Dashboard | 本机没有 Node 生态依赖，且技能要能在纯 Windows + Python 环境跑 |
| story-skills 的 `story` CLI 与完整文件协议 | 它依赖特定目录协议与 CLI 二进制；我们保留"协议思想"，不搬工具链 |
| 天命的 `[REF:xxx]`／`[VAR:xxx]` 引用体系 | 对单机技能过重，且容易在交付里泄漏内部标记（它自己也把"禁止残留 REF"写成硬规则） |
| 各仓库的自建语料库（拆文库、excerpts.csv 等） | 语料涉版权，不搬；只保留"去公开作品里取结构、不取句子"的方法 |
| Chinese-WebNovel-Skill 的仿写检索脚本 | 依赖其本地语料，脱离语料即失效 |
| 扫榜／抓平台数据类能力 | 需要登录态与反爬对抗，属于另一条工程线，不在写作技能内承诺 |

## 四、版权与原创底线（写进流程的硬规则）

1. **借结构不借句子**：可以学节拍、学钩子类型、学模块分工；不许把他人正文段落改几个词就用。
2. **对标拆文只产出"结构卡"**：人物、场景、破局手段必须换成自己的。
3. **引用观点给出处**：写方法论文章时，别人的原话要标来源。
4. **改编他人作品必须获授权**；自己的作品改编保留原始版本与授权记录。
5. **不参与"规避平台识别"的改写**（换词、打乱句序、抽帧镜像变速去重），这是作弊不是创作。
6. **本技能自身是重写产物**：方法与公式来自上述公开仓库（多数 MIT），文字为本技能重写；分发时保留本节作为出处台账。
