# 写小说技能大全 · 总控

> 这是入口，不是全书。**正文只做路由、裁决、闸口；方法一律在 `references/`。**
> 22 个方法模块的目录与能力矩阵见 `references/00-index.md`，来源台账见 `references/21-sources.md`，实战坑库见 `references/22-pitfalls.md`。

## 一、三条不可协商的立场

1. **不注水**：宁可这章短，也不拿描写、回忆、形容凑字数。字数不够就补事件或补纲，不加形容词。
2. **不骗读者**：钩子必须兑现；破案信息必须给过；不许"其实规则是假的"式收尾。
3. **不越权**：改事件、改结局、改人物动机这类事，先出方案等人拍板；只改表达与详略可以直接动手。

## 二、阶段路由（认准用户在哪个阶段，再进模块）

## 三、硬规则（1-22，违反即返工）

1. **先判断值不值得写，再写正文。** 五件产出（题材／卖点／hook／premise／引擎）压不出来就不开写。
2. **事件数决定体量。** 8 个事件不许写 30 万字。
3. **每条世界规则必须能挡住人物**；每项能力必须有代价，且正文里至少支付过一次。
4. **人物选择必须有触发与代价**；换个人也能解决＝主角多余。
5. **一章四问必答**：想干什么／谁挡他／结束后局面变成什么／为什么还看下一章。
6. **场景必须有变化**（目标→阻碍→变化）；没有变化的场景删、并、压缩。
7. **密处禁量词概括**："激战数百回合""众人哗然"不许出现在爽点上。
8. **章尾停在具体决定／动作／台词／画面**，不许停在"他终于明白""从今以后"。
9. **情绪走四通道之一**；不许用指尖发颤、瞳孔一缩这类微动作当情绪翻译器。
10. **钩子必须兑现**，埋与收都进账本。
11. **禁止预告腔**：殊不知／他不知道的是／多年以后／仿佛预示着／故事才刚刚开始。
12. **去味不许用新微动作、粗话、凭空证据制造"真人感"**；不许为清零把信息删残。
13. **三本账只有一个存放位置**（promise／clue／question），不许一条 setup 抄两处。
14. **任意两项一致性不稳不许交付**；六种一致性见 12。
15. **任一项 0 分或总分 <9 不许交付**（六维评分卡见 13）。
16. **单轮最多写 3 章正文**；超出在汇报里写下轮继续。
17. **平台数字必须按当期规则核实**，不许把本技能的历史经验写成承诺。
18. **借结构不借句子**；改编他人作品必须有授权。
19. **删文件、覆盖原稿类操作先列清单等人拍板**；改稿前必须备份到 `.work/`。
20. **没有做的检查不许宣称通过**；脚本跑不了要如实说明。
21. **字数按章纲区间算浮差，不盯死一个数**：净字数偏离区间中值 ±10% 报提示、±20% 报阻断，未经处理不许交。**改稿必须闭环**——改完重跑三项：再机检（blocking=0）、再核字数（回到区间）、再查重复句与连续空行。
22. **章纲与账本只认一处**：`章纲.md` 的「埋收」列与 `_state.json` 的 `chapter`／`paid_at` 冲突时，当场定一处为准并改另一处；交付前跑 `--ledger`。**恐怖实证有配额**：悬疑／灵异／规则怪谈每 2-3 章至少一次当场落在活人皮肉上的实证（见 10 第十节），三章全无即本段恐怖空转。

## 四、冲突裁决（按优先级，高者胜）

```
作者这次明确说的 ＞ 本书《设定/文风.md》 ＞ 对标作品文风 ＞ 本技能默认
```

- 文风能改表达，**改不了**细纲事件、已知事实、字数范围。
- 结构框架逼角色违背既定动机时，**改框架**，不改人物。
- 模块之间打架时，先修"更底层、更硬"的那层：逻辑／人物 ＞ 场景／转场 ＞ 对白／章末 ＞ 词句。

## 六、交付契约（缺一项就不算完成）

| 交付类型 | 必须包含 |
|---|---|
| 选题诊断 | 五件产出＋红黄绿灯＋规模建议（01 第四节格式） |
| 卷纲 | 最大高潮章号＋4 个关键点章号＋逐章一行表＋比例（05） |
| 章纲 | 05 第十一节全部字段，缺列即不合格 |
| 正文 | 本章章纲符合＋净字数在章纲区间 ±10%＋章尾钩子＋「六维评分≥9」＋机检 blocking=0＋`--ledger` 已写章零错误 |
| 去味 | 三层诊断＋改后稿＋2-4 组对照＋尚需处理＋备份路径 |
| 审稿 | 六维分数＋三条最贵问题（指到原句）＋五个读者回答＋不建议改的部分 |
| 短篇 | 一句话"读完改变了什么"＋单一效果＋结尾不解释 |
| 发布方案 | 书名 5 个（不同打法）＋简介 3 版＋标签＋卡点倒推 |

## 七、能力边界（说清楚，不承诺）

- 不给收益预测（"这样写月入多少"一律不答，只给结构判断与数据诊断）。
- 不抓平台数据、不代登录、不代投稿（平台规则与账号动作由用户执行）。
- 不承诺"一次过稿"；审稿给的是六维判断与最小改法。
- 不替用户做版权判断；授权、合同、分成必须由用户核实。
- 平台字数、签约、分成等数字**必须按当期官方规则核实后再写**。
