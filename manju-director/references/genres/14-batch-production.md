# 批量生产：单元化 · 闸口 · 重跑 · 台账

> 一集 90 秒 = 6 条 15 秒；十集 = 60 条；再加图。**没有这套排产法，做到第 3 集就乱**：资产版本对不上、提示词改丢、重跑重到崩。
> 这一份只管"怎么排、怎么卡、怎么记"，不重复创作方法。

---

## 1. 单元化：一切按"条"算，不按"集"算

```
小说 / 创意
  → 分集大纲（每集 60–90 秒）
  → 子镜表（每集 6–8 镜）
  → 15 秒单元（每集 4–6 条）
  → 每条：1 个提示词版本 + 1 组资产引用 + 1 次生成记录
```

**为什么按条**：画布单节点 15 秒，成片靠拼。按条管理才能做到"只重跑坏的那一条"。

---

## 2. 四级闸口（不过不许往下扩）

| 级 | 跑多少 | 通过标准 | 不过怎么办 |
|---|---|---|---|
| **① 单镜样片** | 1 镜 | 人物不变脸、机位对、动作能读、无乱码 | 改提示词结构，不加形容词 |
| **② 单段样片** | 1 条 15 秒（3–4 拍） | 段内动作连贯、段末状态能接下一拍 | 回子镜表拆拍，不要硬凑 |
| **③ 单集成片** | 1 集 4–6 条拼起来 | 节奏成立、字幕位置对、拼接无跳 | 补过桥物/状态锁（`10` §3） |
| **④ 批量** | 其余集 | ①②③ 的模板已冻结 | 模板没冻结就扩量 = 全部返工 |

**模板冻结 = 这几样固定下来不再改**：画风参数 + 排除清单、角色资产与 @图映射、镜头模板（每类镜一句式）、字幕规格、配音音色。

---

## 3. 排产顺序（先什么后什么）

1. **先资产图，后视频**：角色定妆 / 三视图 / 场景板 / 道具板先出齐，再动视频。图上没定的，视频里必乱。
2. **先主镜，后群演空镜**：主角特写、关键情绪镜先跑通，群像和环境镜最后补。
3. **先难后易**：打斗、变身、多人同框先做（这些最容易崩，早崩早改）；单人对白、空镜后做。
4. **同场景集中跑**：一个场景的所有镜一次跑完，省得反复切资产与光向。
5. **每集留 1 条余量**：用来补替换（某条崩了不会卡住整集）。

---

## 3.1 数据依赖：资产与分镜，谁先谁后

这一条常被搞反，反了就是白跑。

**两条路线，按工具形态选**：

| 路线 | 顺序 | 适用 | 代价 |
|---|---|---|---|
| **A 结构先行**（工程型工具：LocalMiniDrama 这类） | 剧本 → 提取角色/场景/道具 → 建资产记录 → 生成分镜 → 出图出视频 | 自动化流水线、批量生产、软件里跑 | 分镜写的时候**资产还没定**，只能按文字描述引用，容易与最终定妆不符 |
| **B 创作先行**（人工创作：本技能主路线） | 剧本 → 分镜（含资产需求） → 反推资产清单 → 定妆 → 回头锁引用 | 先看戏、再定人，创意优先 | 分镜定稿后要**回头改一遍引用**，返工一次 |

**裁决**：
- 走软件流水线（有数据库、有角色库/场景库）→ 用 A。**绝不能跳过资产提取直接生成分镜**：出来的分镜里角色列表是空的、场景是 null，后面生图没有参考，人物必飘。
- 走画布手工（本技能的 Toonflow 路线）→ 用 B，但必须多做一步：**分镜表里每一镜先写"资产需求"字段**（谁、在哪、拿什么），分镜写完立刻汇总成资产清单，再定妆。这样返工的是引用编号，不是构图。
- **两条路线都不能省的**：资产编号（`@图N`）在分镜表里就要占位，不许等定妆完再回头猜哪张是哪张。

## 3.2 异步任务与失败隔离（工程口径）

批量跑的时候，最怕"一条崩了拖垮整批"。三条：

1. **一镜一任务，不要串成一条大链**。整集串一条，第 7 镜崩了，前 6 镜的成果拿不出来。同批里各条互不依赖，失败了只丢那一条。
2. **轮询有上限，不无限等**。合理参数：首次等 0.5s，之后每 2s 查一次，查 60 次（约 2 分钟）还没完 → 判超时，转后台继续，不要阻塞整批。超时**不等于失败**，重跑前先查真实状态。
3. **同因失败只重试有限次数**。同一提示词同参数，最多重跑 3 次；3 次同因崩 → 判定结构问题，改提示词结构或换机位，不要第 4 次硬抽（同机位第 4 次基本还是崩）。

**恢复时的三条禁令**（来自 DramaClaw 的工程实践，值得抄）：
- 不要为了"让它跑通"而提交**缩减版**任务（少几个节点、空图、探针节点）—— 那等于交付一个错的东西。
- 超时/失败后重跑前，先**核对已完成的部分**，别把已经付费生成成功的镜头再生成一遍。
- 校验类失败只在**报错点名的字段**上改，不要整份重写。

## 4. 重跑策略（不是"再抽一次"）

| 情况 | 做法 |
|---|---|
| 偶发崩（脸歪、手糊、乱码） | 同提示词重跑 1 次；同因再崩 → **改结构**，不是改词 |
| 系统性崩（每条都换脸、每条都越轴） | 停跑。回资产锁与固定块，修清单，再跑 |
| 动作读不出 | 拆拍（一镜一动作），不要加"更激烈" |
| 拼接跳 | 补过桥物 + 状态锁，不要重生成两段 |
| 一条重跑 3 次仍崩 | 换机位或换景别。同一机位第 4 次基本还是崩 |

**记录规则**：每次重跑记"第几次 / 改了什么 / 结果"。改了什么必须写具体（改了哪一句、加了哪条负向），不许写"调了一下"。

## 5. 台账（一集一张，缺字段就是漏）

| 字段 | 内容 |
|---|---|
| 集号 / 镜号 | `EP03-S07` |
| 时长 / 拍数 | 15s / 4 拍 |
| 资产引用 | `@图3 角色A / @图7 场景 / @图12 道具` |
| 提示词版本 | `v2`（含改动摘要） |
| 模型与参数 | 读 `node:getConfig` 的真实值，不抄记忆 |
| 生成结果 | 通过 / 崩（崩点：脸/手/轴/字/物） |
| 重跑次数 | 1 / 2 / 3 |
| 字幕 | 有无、条数、语言 |
| 备注 | 待补、待确认 |

**跨集台账另有一张**：角色/服装/场景/道具/音色的**编号与变更记录**。同一角色换装必须记"哪一集换的、为什么"，否则下一集观众认不出。

## 6. 成本与时间：只给算法，不给承诺

**不要报具体秒数和积分**（会变，报了就是错）。用这个算法估：

```
单条耗时 ≈ 生成耗时 + 排队 + 抽帧自检 + 平均重跑次数 × 生成耗时
总条数 = 集数 × 每集条数
总时长 ≈ 总条数 × 单条耗时 + 资产图耗时 + 剪辑字幕耗时
```

经验比例（用于排期，不作承诺）：
- 资产图 ≈ 视频总耗时的 20–30%
- 重跑 ≈ 首次生成耗时的 50–100%（前 2 集更高，模板冻结后下降）
- 剪辑字幕 ≈ 每集 10–20 分钟

**降本顺序**：先砍群演与空镜 → 再合并同场景镜 → 再减少每集条数（靠单条 15 秒装更多信息），**最后才考虑降分辨率**。

## 7. 目录与命名（乱在这里，后面全乱）

```
项目名/
├── 01_剧本/          分集大纲.md、EP01.md…
├── 02_分镜/          EP01_子镜表.md…
├── 03_资产/          A-角色/ B-场景/ C-道具/（@图编号与文件名一致）
├── 04_提示词/        EP01_S07_v2.md（一镜一文件，版本只增）
├── 05_生成/          EP01_S07_v2.mp4
├── 06_成片/          EP01_v3.mp4
└── 99_台账/          单集台账.md、跨集台账.md、复盘.md
```

**命名铁律**：资产文件名里的编号必须和 `@图N` 对得上；提示词文件名必须带镜号与版本；成片只留最新版 + 上一版。

## 8. 批量期最常见的五个坑

1. **模板没冻结就扩量** —— 做到第 5 集发现画风漂了，前面全废。
2. **资产版本混用** —— 第 3 集用了旧定妆图，人物像换了个人。
3. **不记重跑原因** —— 同一个崩点重复踩 10 次。
4. **一次排太多** —— 40 条一起跑，崩了一半，分不清是结构问题还是偶发。
5. **剪辑放到最后** —— 拼不起来才发现缺过桥镜、缺特写、缺收尾。
