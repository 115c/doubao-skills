# 能力边界：能做什么、做到多少、超了怎么办

> 这一份是**动手前必读的第一页**。所有承诺都要从这里出，不许凭感觉答应。
> 数据源：Dreamina《Seedance 2.5 User Guide》（官方 wiki 快照，文档版本 419，整理于 2026-08-16）+ 本画布节点实测。**UI 与本文冲突时以当前 UI 为准，不许自行编造新上限。**

---

## 1. 三层口径，别混着说

| 层 | 谁说了算 | 用途 |
|---|---|---|
| **官方能力** | Seedance 2.5 官方指南（本文件 §2–§4） | 判断"这件事模型本身能不能做" |
| **本画布节点** | `node:getConfig` 实测（当前：15s / 720p / 16:9） | 判断"这台机器这次能不能跑" |
| **稳定性建议** | 官方经验值（§4） | 判断"能跑，但大概率不稳" |

**写法**：先按官方判断可行性 → 再按画布判断可执行性 → 再按稳定性提示风险。三层都过才动笔。

## 2. 模式选择表（选错模式=白跑）

| 模式 | 官方时长/来源规则 | 什么时候用 | 画布落地注意 |
|---|---|---|---|
| **基础（文/图生视频）** | 输出 4–30 秒 | 单拍、无参考驱动 | 画布节点上限 15s，超了拆条 |
| **首帧模式** | 4–30 秒 | 有定妆图，要它开镜就对 | 首帧图必须与后续镜一致 |
| **首尾帧模式** | 4–30 秒 | 两端状态已知，中间要它补 | 首尾帧的光向、机位、比例必须同源 |
| **全能参考（Omni Reference）** | 4–30 秒 | 身份/场景/道具/动作多种参考同时作用 | 参考张数越多越不稳（§4） |
| **长视频（Long Video）** | 30–180 秒 | 用户明确要"一条 30 秒以上" | **画布节点跑不了**，必须拆条拼接；不要拿它当"省事模式" |
| **视频续写（extension）** | 源视频须 < 30 秒；官方广告最多嵌套到 60 秒 | 接着已有片头/片尾加段 | 只能描述**新增区间**，见 `10-community-banks.md` §1 |
| **智能编辑 / 标记编辑 / 视频编辑** | 源视频建议 ≤ 20 秒 | 改一个元素，其余锁死 | 见 `10-community-banks.md` §2 |
| **无缝衔接** | 两条有序源视频 | 两段接成一段 | 见 `10-community-banks.md` §3 |
| **白模渲染（Clay Renderer）** | 粗模 / 细模参考视频 | 用灰模定运动与构图，再渲染成片 | 粗模路径更稳；必须声明"不保留灰模材质与视口元素" |
| **音频驱动** | 音频 2–30 秒，最多 10 条合计 ≤30 秒 | 对口型、按音轨卡点 | 见 `12-reference-grammar.md` §5 |

**别犯的错**：不要因为用户说"30 秒"就自动切长视频模式。30 秒要精确控制节奏时，用**时间轴 30 秒**写法（`10-community-banks.md` §8）更稳；只有用户明确要长视频行为才切。

## 3. 输入规格（上传前先自查）

### 图片
- 格式：JPEG / PNG / WebP / BMP / TIFF / GIF / HEIC / HEIF
- 宽高比（宽/高）：**> 0.4 且 < 2.5**
- 边长：**300–6000 px**；单张 **< 30 MB**；单次请求体 ≤ 64 MB（大图别用 Base64）
- 数量：2.5 单次最多 **30 张**

### 视频
- 格式：MP4 / MOV；分辨率 480p–4K；宽高比 0.4–2.5；边长 300–6000 px
- 总像素 409,600–8,295,044；单片 ≤ 200 MB；帧率 24–60 FPS
- 单片标称时长 **2–30 秒**（实现容差约 1.8–30.2 秒）
- 数量：最多 **10 条**，合计标称时长 ≤ 30 秒

### 音频
- 格式：WAV / MP3；单条 ≤ 15 MB；请求体 ≤ 64 MB
- 单条时长 2–30 秒（容差同上）；最多 **10 条**，合计 ≤ 30 秒
- 2.5 支持**纯音频参考**输入

## 4. 稳定性建议（不是硬拒，是"能跑但会崩"的预警）

| 项 | 建议范围 | 超了会怎样 |
|---|---|---|
| 由参考**视频/音频**驱动的主体数 | 1–5（6–10 会掉稳定性） | 主体特征漂移、串脸 |
| 参考视频/音频时长 | 5–10 秒更好 | 越长越容易把无关动作也带进来 |
| 静图里的主体数 | 1–8（9–12 会掉） | 多主体互相污染 |
| 全用静图供身份时 | 8 个以内算正常，不必因为"超过 5 个"就报警 | 与上一条同口径 |
| 超过 5 个主体时 | **拆成多张单视图图**，不要一张图塞多视图 | 一张多视图的稳定性**低于**多张单视图 |
| 视频编辑的源片 | ≤ 20 秒更好 | 更长可能不报错但结果不稳 |
| 视频编辑的参考图 | 1–5 张更好（6–8 掉稳定性） | 同上 |

**关键一句**：多张单视图 > 一张拼了多视图的图。做角色设定板时按这条拆。

## 5. 超限处理流程（五步，别跳）

1. **按实际计数**：只数真实交付的、或用户明确声明的素材。不许把"计划里的占位"算成资产。
2. **能查的都查**：格式、单片时长、合计时长、体积、比例、张数。
3. **硬上限超了 → 停手**，先给具体方案：减少数量 / 拆条 / 裁剪 / 转码 / 换模式。不要硬写提示词再指望它通过。
4. **拿不到元数据 → 不许编**。只在"缺这个信息会挡住提交"时，加一句前置提醒。
5. **在硬限内但超出稳定性建议 → 继续做，但明确标注风险 + 给一个简化选项**。

## 6. 「别承诺」清单（10 条，逐条对照自己的话）

1. 不承诺"提示词能突破上传限制或 UI 限制"—— 做不到。
2. 不承诺"一次生成就是成片"，尤其 30 秒以上、多人打斗、强情绪对白。
3. 不承诺"改一个元素只改那一处"，只能"让它尽量别动别处"。
4. 不承诺"百分百不换脸"，只说"锁了哪些特征、崩了怎么修"。
5. 不承诺"字幕/招牌/文字能写对"—— 一律用后期上屏字。
6. 不承诺"配乐、歌词、真人对白的音色可完全还原"。
7. 不承诺"某条片子一定能过平台审核"。
8. 不承诺具体生成耗时和积分消耗数字，只给估算方法（见 `14-batch-production.md`）。
9. 不承诺"参考图里的不存在的东西会被补出来"—— 图里没有的，提示词必须写。
10. 没跑过的模型/版本，不许把它当"推荐值"写进交付。

## 7. 官方 vs 本画布：差在哪、怎么落

| 项 | 官方 2.5 | 本画布实测 | 落地做法 |
|---|---|---|---|
| 单条时长 | 4–30s（长视频 30–180s） | 15s | 按 15s 切单元，多条拼；30s 以上按幕组织（`10-community-banks.md` §8） |
| 分辨率 | 480p / 720p（参考流程可到 4K） | 720p | 别写要求 4K 细节的锚点，720p 撑不住 |
| 画幅 | 0.4–2.5 之间 | 16:9 默认 | 竖屏交付要显式改 9:16，并同步改机位策略 |
| 参考素材 | 图 30 / 视频 10 / 音频 10 | 节点按注册能力 | 动手前 `node:getConfig` 读一次真实注册项 |
| 音频驱动 | 支持 | 看节点是否注册 | 未注册就不写"音频驱动"，改成配音后期贴 |
