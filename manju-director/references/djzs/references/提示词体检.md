# 提示词体检（交稿前必跑）

两条路：能跑脚本就跑 `tools/prompt_lint.py`；不能跑就照下面的表逐条打勾。
**不通过不许交给用户**，也不许直接拿去生成。

---

## 一、机检项（脚本能查）

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 六字段齐全 | `subject_definitions` / `summary` / `retention_analysis` / `detailed_description` / `overall_soundscape` / `non_diegetic_music` 都在 |
| 2 | 字段顺序 | 按上面顺序出现 |
| 3 | 镜号 | `[Shot 1]` 开头，连续递增，不跳号 |
| 4 | 时间戳 | `[Shot 1]` 无时间戳；后续每个都有 `At MM:SS.mmm`；严格递增；≤ 时长 |
| 5 | 引用闭合 | 用到的 `<Subject N>` / `<Picture N>` / `<Video N>` / `<Audio N>` 都在 `subject_definitions` 里定义过；没有悬空编号 |
| 6 | 台词格式 | 每句台词在 `<d>[Chinese] …</d>` 内，并绑 `(S1)`/`(S2)` |
| 7 | 无对白锁嘴 | 没台词时必须出现"嘴唇闭合"或"无对白" |
| 8 | 禁用词 | 不出现：杰作、8K、超清、电影级、氛围感、大片感、震撼、唯美、极致、完美、（masterpiece/best quality/ultra detailed） |
| 9 | 平台参数 | 正文里不出现分辨率/步数/seed/采样器/负面提示词字段 |
| 10 | 字数 | 六字段总字数 350–900 字（单镜 250–450；多镜按镜数累加） |
| 11 | 声音点 | `overall_soundscape` 至少 3 个分号分隔的声音项 |
| 12 | 配乐 | 写了乐器+节奏+动态，或明确 `N/A` |
| 13 | 镜头六要素 | 每镜都有景别/角度/机位运动/焦段/光线/起幅落幅；缺 3 项判 FAIL |
| 14 | 互斥动作 | 同一句里不做相反的事（跑+停下、拔刀+收刀、睁眼+闭眼）→ FAIL |
| 15 | 物理支撑 | 出现腾空/击飞/翻滚，必须写蹬地/借力/落地，否则 FAIL |
| 16 | 攻击方向 | 劈/砍/踹/刺/撞必须写方向或目标，否则 WARN |
| 17 | 动作密度 | 每镜动作节点 ≤ (时长/2+1)×2，超了 WARN |
| 18 | 运镜冲突 | 同句推+拉、摇+移（无「推拉/摇移」）→ WARN |
| 19 | 抽象词 | 气势/压迫感/爆发/震撼等合计 >3 次 → WARN |
| 20 | 参考上限 | `<Picture>` ≤9、`<Video>` ≤3、`<Audio>` ≤3，超了 FAIL |

## 二、人读项（脚本查不了）

| # | 检查 | 不通过的样子 |
|---|---|---|
| 13 | 信息单元数 | 动作节点 <3、空间锚 <2、光 <1、镜头 <1、结束态 <1 |
| 14 | 可拍性 | 出现"情绪到位""气氛紧张"这类无法拍的词 |
| 15 | 一致性锚 | 人物五件套、场景结构、光向与上一镜冲突 |
| 16 | 时长匹配 | 5 秒写了 4 个动作；15 秒只有 1 个动作 |
| 17 | 参考用途 | 一张图既当外观又当构图又当动作（一图多用必糊） |
| 18 | 横屏构图 | 出现竖屏式"上下堆叠""头顶留白"（默认 16:9） |

## 三、评分（100 分制，≥80 才交）

| 项 | 分值 | 拿满的条件 |
|---|---|---|
| 信息单元 | 30 | 动作节点 ≥3、空间锚 ≥2、光 1、镜头 1、结束态 1，全部带秒点 |
| 动作逻辑 | 20 | 每镜有动作表依据（发力点/轨迹/接触点/结束态），无互斥、无空中飘、攻击有方向 |
| 镜头语言 | 20 | 六要素齐全（景别/角度/机位运动/焦段/光线/起落幅），一镜一个主运镜 |
| 一致性锚 | 15 | 人物五件套 / 场景结构 / 光向 与全集锚一致 |
| 声音设计 | 10 | 三层齐全（底噪、动作声带秒点、人声或静默）+ 配乐判断正确 |
| 语言质量 | 5 | 无禁用词、无空话、无平台参数，中文叙述 + 英文格式元素 |

扣分速查：出现一个空话 −3；少一个单元 −5；时间戳错 −10；引用悬空 −10；一镜多运镜 −8；字数超 900 −5；缺镜头六要素 −6/项；互斥动作或无支撑腾空 −10；抽象词过多 −5。

## 四、机检脚本（Toonflow 内直接跑，无需装 Python）

Toonflow 自带 `sandbox` 工具，里面就有 `python3`（标准库），把脚本和提示词一起导进去执行即可：

```
sandbox({
  command: "python3 prompt_lint.py 提示词.md --duration 6",
  imports: [
    { path: "<技能目录>/tools/prompt_lint.py", target: "prompt_lint.py" },
    { path: "<工作区>/提示词.md", target: "提示词.md" }
  ]
})
```

要点：
- `imports` 里的 `path` 可以是工作区相对路径，也可以是 `skillOperator` 返回的全局技能文件绝对路径（即技能里 `tools/prompt_lint.py` 的绝对路径）。
- 沙箱每次都是全新的内存文件系统，**脚本和提示词都必须显式 import**，不会自动带相邻文件。
- 禁网、无 pip；脚本只用标准库（re/json/sys/argparse），不需要额外依赖。
- 图片用 `--kind image`，不加 `--duration`。
- 输出最多 64 KiB；把 stdout 里的 `PASS/WARN/FAIL + 评分 + 问题列表` 原样告诉用户。

本机装了 Python 也可以直接：`python prompt_lint.py 文件.md --kind image`。

## 五、命令行跑法

```
python tools/prompt_lint.py <提示词文件.md> [--duration 6]
```

输出：`PASS` / `WARN` / `FAIL` + 每条问题的行号与原因 + 分数。
`FAIL` 必须改；`WARN` 自己判断，交稿时说明。

## 六、闸口流程

```
写（模板库）→ 体检（本文件）→ 自评分 ≥80 → 交用户确认 → 生成 → 抽帧自检 → 收样本/记反例
```

任何一步不过，回到上一步，不要把问题带进生成。

## 七、道具多视角板（`--kind prop`）

道具不合格的根因几乎都是「只写了名字」：模型没见过这件东西，只能自由发挥（秤画成木架、木棍画成柴火、窝窝头画成石头）。

跑法：`python3 prompt_lint.py 道具.md --kind prop`；视频用 `--kind video --duration 6`（Toonflow 内用 `sandbox` 工具，imports 带脚本与本文件）。

机检项：
1. **零件数**：`结构：由 A、B、C…组成` 里至少 3 个零件；
2. **视角/形态数**：至少 2 个，且要写清「怎么用」（被拎起/放桌面/插在鞘中/拔出/掰开）；数量不固定，按分镜里的出现方式定 2–4 个；
3. **尺寸**：长度或直径，或「单手可握/双手抬」；
4. **材质**：木/铁/铜/陶/布/皮…；
5. **风格**：至少 2 个（写实/低饱和/做旧…）；
6. **背景**：纯中性灰/纯色；
7. **参照物**：出现「旁边放/一只手/硬币当参照」→ 直接 FAIL（「无参照物」这种否定句不算）；
8. **形态**：一个形态词都没有 → WARN（说明视角是按模板套的，不是按戏里怎么用）。
9. 禁用词、平台参数、正文比例、「同上」。

评分与闸口同前：**≥80** 才交；低于就把缺项补上再跑。
