# 六机制审查（六槽）

任何动手之前，过六道问；六道全走完才放行。

这套机制的实测结论只有一条：**整套用有效，拆开单用无效甚至有害。** 所以这里的重点不是"多想想"，而是"六个格子逐个填满，每格都有可验证产出"。

## 启用判定

动手前先判断这件事属于哪一类：

| 情形 | 处理 |
| --- | --- |
| 纯只读、会话内可撤销、错了也没成本（查资料、读文件、跑一次只读命令） | 不启用，直接做 |
| 有副作用或不可逆：写/覆盖用户文件、破坏性命令、改配置、部署发布、发消息邮件、批量处理、花钱、对外承诺 | 启用，六问全走 |
| 用户要求审查方案/决定/风险，问"值不值得做""有没有坑""该不该动手" | 启用，以用户给出的对象为审查对象 |
| 应急、人身安全优先 | 先处置，事后补审 |

判断不清就按"启用"处理：六问走完的代价，远小于一次不可逆操作的代价。

## 三条铁律

1. **整套用，不许拆。** 六问是一个组合，不是六条可以各取所需的建议。实测单条使用全部低于什么都不做，其中"只强调最坏结果"比不加还低 25 个百分点。不得只挑"退路"或"依据"来做，也不得把六问改成"可以从任一条开始"的自选清单。
2. **每问必须有产出物。** 写下、跑出、查到才算。心里过一遍不算，"我考虑过了"不算。
3. **判不了就写「判不了」。** 硬猜比空着更糟。写了「判不了」必须同时写"要判出来还缺什么"。

## 六问与产出契约

| # | 问 | 合格产出（必须落到具体东西上） | 不合格写法 |
| --- | --- | --- | --- |
| 1 | 目标：我要达成什么？不做哪些事？ | 一句可衡量的结果 + 一句明确的不做边界 | "做好""优化一下""把这事情办了" |
| 2 | 条件：我依赖的东西真实存在吗？ | 一条验证记录：文件路径、命令是否跑通、接口返回什么 | "应该没问题""之前用过" |
| 3 | 退路：最坏会怎样？我扛得住吗？ | 一个具体动作：备份在哪、回滚怎么做、止损点是什么 | "不行就回滚"（没说从哪回、怎么回） |
| 4 | 影响：这事影响谁？他们知道吗？ | 谁受影响 + 当前告知状态（未告知也照实写） | "影响不大""大家都懂" |
| 5 | 依据：我是有证据，还是凭感觉？ | 一条可指认的证据（路径/行号/日志/数据/链接），或明确写「不确定」 | "凭经验""一般情况都这样" |
| 6 | 收尾：之前答应的事兑现了吗？摊子收了吗？ | 列出还没结的事，含本次动作会留下的临时物与中间状态 | "都处理好了""没有遗留" |

每一问的判据细节、典型空话的改写示例、常见误用，见 `references/gates.md`。机制背后的实验数据与适用边界见 `references/evidence.md`。可选增强（风险分级、事后回填、归因库）见 `references/extensions.md` —— **属未验证扩展，默认不启用**。

## 执行流程

1. **定对象**：用一句话写清"这次要执行的那个动作"，不是"要做的那件事"。一个动作一套六问；一次做多件事就把动作拆开，分别走。
2. **逐格填**：按 1→6 顺序，不跳格、不倒序。顺序本身是机制的一部分——目标没定就去评估影响，会把边界当成事实。
3. **标记判不了**：任何一格填不出真东西，就地写「判不了 + 缺什么」。
4. **放行判定**：
   - 六格都有合格产出 → 执行。
   - 有空格 → 先补；补得上就重走一遍，补不上就**不做**，把缺的那格交回用户，或把动作缩小成可验证的一步。
   - 有「判不了」且该格直接决定不可逆后果 → 不做，停下说明。
5. **事后回填**（可选）：动作完成后回看六格，记下预判与实际的偏差。

## 输出格式

**精简模式**（默认，中低风险、对话中顺手做）：六行，不写小作文。

```
1 目标：____｜不做：____
2 条件：____（已验证：____）
3 退路：____触发____时，执行____
4 影响：____｜已告知 / 未告知
5 依据：____ / 不确定
6 收尾：未结：____
放行：可做 / 待补第X格 / 不做
```

**完整模式**（高风险或用户明确要求审查）：表格形式，每格附证据位置（路径、行号、命令输出、链接）。

## 禁止行为

- 不得把六问改写成通用思考清单。实测打乱措辞与结构后效果明显回落，效果来源是这套特定措辞和固定顺序，不是"多加思考"这个动作本身。
- 不得为了格子好看而填假证据。假证据比「判不了」危害更大，它会让后续判断建立在虚构前提上。
- 不得在审查结束后顺手扩大动作范围。六问只对已写明的那个动作负责。
- 不得把"六格填满"当成结论正确的背书。这是防错清单，不是正确性证明；它拦住的是已知类型的低级失误，不是保证决策最优。
