# 实验数据与适用边界

这些数据的用途只有一个：让使用者知道**为什么必须整套用**，以及**这套机制能证明什么、不能证明什么**。引用时不要超出下表范围。

1. 整套使用相对空白对照稳定提升约 8–10 个百分点，且满分率提升幅度更大。
2. 效果来自机制的特定措辞与固定顺序，不是"多加一步思考"（"多想一步"组反而更差；打乱文本组明显回落；通用工程质检清单无显著增益，p=0.44）。
3. 单条拆开使用全部低于基准，六问必须整套用。

## 二、MiMo 模型场景实测

| 场景 | 结果 |
| --- | --- |
| 写代码：从 w3x 文件读取地图名 | 8.1 秒，一次正确，真实地图验证通过 |
| 施工决定审查：列出最该拦的风险 | 49 秒，三条全部命中，其中"试压记录缺压降值"是原始场景未写明的盲点 |
| GitHub 真实代码审查：TheAlgorithms/Python 的 quick_sort.py | 列出三条问题，实测命中 2/3（NaN 被静默吞掉＝真；单元素返回原列表的别名副作用＝真；"只实现 `__lt__` 的对象会报错"＝假，Python 会反向调用） |

关键结论：**模型会给出一本正经但错误的结论。** 它适合当审查助手，每条结论仍需人工或工具验证。第5问（依据）就是为这个失效模式准备的。

## 三、这些数据能证明什么

- 在有明确规则、可重复对局的场景里，整套六问能显著提升行为的稳健性。
- 结构化不等于有效：一张看起来同样严谨的工程清单没有增益，说明起作用的是这套措辞与顺序。
- 拆条会劣化，且劣化最严重的是"只盯最坏结果"。

## 四、这些数据不能证明什么

- **不能证明通用决策质量提升。** 实验场景是规则明确、结果可量化的博弈，不是开放的战略、创意或人际决策。
- **不能证明专业判断正确。** 真实代码审查命中 2/3，说明它拦得住格式类失误，拦不住领域知识型错误。
- **不能代替人为判断。** 六格填满只说明"该问的都问了且有产出"，不说明结论正确。
- **未覆盖的场景**：创意发散、长期战略（多数前提无法验证）、紧急处置（没有走流程的时间）、纯粹审美或偏好类选择。

## 五、因此在本技能里的落地约定

- 六问固定，不增不减，顺序不变。
- "多想一步""加一张通用清单"不构成对机制的替代或增强。
- 任何新增规则都按未验证处理，放在 `references/extensions.md`，默认关闭。
