# 可选增强（未验证）

以下三条都是对原机制的扩展，**没有做过对照实验**。原机制的效果来自"六问固定 + 每问有产出"这个结构，任何新增规则都可能稀释它。使用约定：

- 默认关闭。只在明确需要时打开，并向使用者说明"这是未验证扩展"。
- 打开时不得改动六问本身的数量、措辞与顺序。
- 如果发现开启后反而更容易放过问题，关掉。

---

## 扩展 A：按风险调节证据厚度（不是调节问几个）

容易误用成"低风险就少走几问"——那等于拆条，实测有害。正确用法是：**六问照走，改的是每格证据要多硬、谁来复核。**

| 风险档 | 典型动作 | 六问照走，但 |
| --- | --- | --- |
| 低 | 会话内可撤销、影响仅限自己、错了能立刻改回 | 第2、3问各一行说明即可，不必留快照 |
| 中 | 动到用户文件、共享配置、对外可见的提交 | 第2问要留验证命令或输出，第3问要写明回滚命令，第4问要写告知状态 |
| 高 | 不可逆（删除/覆盖/对外发送/付费）、生产环境、多人依赖、无法回滚 | 每格附证据位置；第3问必须有可恢复的备份且验证过能恢复；第4问必须已告知或明确承担未告知后果；执行前由第二人复核 |

降档的唯一理由是"可撤销"，不是"事情小"或"时间紧"。

## 扩展 B：事后回填

动作完成后，用同一张表回填一行实际结果，对照六格看偏差：

| # | 回填要看什么 |
| --- | --- |
| 1 | 目标达成了吗？边界有没有被冲破？ |
| 2 | 有没有出现没验过的依赖失败？ |
| 3 | 退路触发了吗？触发时它真的有用吗？ |
| 4 | 实际影响面和预判差在哪？漏了谁？ |
| 5 | 当初的判断对错如何？错在哪一类证据上？ |
| 6 | 留下了什么新摊子？ |

价值在于：**六问的预判能力只能靠偏差记录修正**，没有回填，机制永远停在第一次的水平。

## 扩展 C：错误归因库

把每次踩到的坑归到六问里的某一格，累积后反哺 `references/gates.md` 的提示项。

- 目标类：返工、范围失控、做完了但没人要
- 条件类：临门一脚失败（权限、磁盘、编码、版本、占用）
- 退路类：回不去、恢复不了、止损太晚
- 影响类：别人被意外改变、协作中断、对外解释不清
- 依据类：一本正经说错话、把猜测当事实
- 收尾类：留下垃圾、承诺跳票、下次接手困难

经验阈值：某一格累计出现 3 次同类失误，就把那一条具体检查项写进 `references/gates.md`，而不是只写"注意 XX"。

## 扩展 D：嵌入工具链（AI / 工程场景）

- 六问设为输出前必经的思考节点，按 1→6 顺序输出，禁止跳步、禁止合并成一格。
- 可验证的条件项（文件、命令、接口）先真的跑一次，把输出写进第2问，再继续往下。
- 第5问强制标置信度；低于阈值一律输出「不确定」，禁止给笃定结论。
- 最终结论产出后，用六问反向自查一遍，确认没越界、没漏格，再交付。

注意：这一条的价值与风险都在"强制"上。强制能拦住偷懒，但也可能让输出变长变慢；先在低风险任务上试，确认不劣化再用。
